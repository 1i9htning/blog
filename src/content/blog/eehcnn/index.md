
注意：

- **类的基本思想：数据抽象和封装**
- **数据抽象**是一种依赖于**接口和实现分离**的编程技术
- **类的接口**包括用户所能执行的操作
- **类的实现**包括类的数据成员、负责接口实现的函数体以及定义类所需要的各种私有函数
- 封装实现了类的接口和实现的分离
- **抽象数据类型：**类的设计者考虑类的实现过程。类的使用者只需要抽象地思考类型做了什么，而无需了解类型的工作细节
- **定义在类内部的函数是隐式的inline函数**
- **成员函数的声明必须在类内部，定义可以在类内部也可以在类外部**
- **组成外部接口的非成员函数定义和声明都必须在类外部，习惯上把这些函数的声明和类写在同一个头文件中**
- **编译器先编译成员声明，然后才轮到成员函数体。所以即使数据成员的声明在某个函数体之后，这个函数体也能调用这些声明在它之后数据成员**
- **定义在类外部的成员函数/构造函数需要在函数名前使用类的同名作用域**
- **负责输出内容的函数原则上不应该控制换行或者其他格式，这样可以确保由类的使用者代码来决定是否换行**
- **一般来说，最好在类开始前或者结束前集中集中友元声明**
- **建立类对象时，可以直接使用类名作为类型名，也可以在最前面加上class或者struct**
- **养成将成员函数写在类外部的习惯（有时要加上inline）**
- **如果成员是引用类型或者常量就必须有构造函数初始值列表或者类内初始值。因为这样的成员一旦初始化后就无法改变，所以建议使用构造函数初始值列表而非类内初始值**
- **如果一个构造函数中，所有的形参都有默认实参，则它就相当于默认构造函数！**
- **使用默认构造函数时不能使用调用运算符！那样会变成一个函数声明！**
- **定义类的对象时，如果采用花括号的列表初始值方式初始化，则列表初始值也必须与某一个构造函数参数相匹配**
- **想要确保只定义一次类的静态成员，一般将类的静态成员定义存放在头文件**
- **为了安全起见，既是一个常量静态数据成员在类内被初始化了，在外部也应该提供定义语句**
- **静态成员可以作为默认实参，非静态数据成员不能作为默认实参！**
- **只有整数类型的常量静态成员能够执行类内初始化！且初始值必须是常量表达式。因此，类内初始化的静态成员也是一个常量表达式**

## 类的声明：

将类的定义和声明分开来，仅仅声明类而不定义它，这种声明叫做**前向声明**

前向声明向程序中引入了类名并且指明它是一个类类型，**这个类在它声明之后定义之前是一个不完全类型**，即我们直到它是一个类，但不清楚它到底包含哪些成员

**不完全类型使用场景非常有限：**定义指向这种类型的指针或引用，也可以声明（**不能定义！！！**）以不完全类型作为参数或返回类型的函数

**对于一个类来说，在创建它的对象时，该类必须被定义过。否则，编译器无法了解这样的对象需要多少的存储空间**

**只有类被定义过之后，才能使用指针或者引用访问其成员**

**只有当类全部完成时才算被定义完成，因此一个类的成员的类型不能时该类自己（静态成员除外）。有一个例外情况是：直到类被定义后数据成员才能被声明成自身这种类类型的引用或指针。只要声明了类名后，就允许创建它的引用或者指针，因此定义类时它的成员允许是自身类型的指针或引用**

## 类对象的初始化：

可以为数据成员提供一个类内初始值。创建对象时，类内初始值将用于初始化数据成员。没有初始值的成员将被默认初始化

**使用类内初始值不能使用圆括号！！！**可以使用花括号或者等号

## this指针：

**成员函数通过一个名为this的额外的隐式参数来访问调用它的那个对象**

**当调用一个成员函数时，用请求该函数的对象的地址来初始化this：**比如一个Sales_data类对象book，调用它的成员函数isbn()时，调用形式为book.isbn()。编译器负责把book的地址传递给isbn的隐式形参this，可以等价地认为编译器将该调用重写为这样的形式Sales_data::isbn(&book)，其中，调用Sales_data的isbn成员时传入了book的地址

在成员函数内部，直接使用调用该函数的对象的成员，而无需通过成员访问运算符来做到这一点就是因为this所指的正是这个对象

**任何对类成员的直接访问都被看做this的隐式引用。也就是说，比如一个成员函数isbn()使用数据成员bookNo时，它隐式地使用this所指向的成员，就像我们写成this->bookNo一样（(\*this).bookNo）**

**this形参是隐式定义的，所以不能有同名形参或变量**

**可以在成员函数内部显示地使用this，但是没必要：string isbn()const {return this->bookNo;}**

**this的目的总是指向“这个”对象，所以this是一个常量指针！我们不允许改变this中保存的地址**

### 显示使用this指针的优点：

- 更明确，减少误读的可能性
- **可以使用名称与成员名相同的形参**

```c++
void setAddr(const std::string &addr) { this->addr = addr; }//将形参addr赋值给数据成员addr
```

## const常量成员函数：

在成员函数的形参列表后添加const关键字，**这里的const作用是修改隐式this指针的类型**

**默认情况下，this的类型是指向该类类型非常量版本的常量指针**
尽管this是隐式的，但它仍然需要遵循初始化规则，意味着（默认情况下）我们不能把this绑定到一个常量对象上。即我们不能再一个常量类类型对象上调用普通的成员函数

**常量对象、常量对象的引用都只能调用其常量成员函数**

```c++
Sales_data& combine(const Sales_data &sd)
{
    units_sold += sd.units_sold;//售出数量
    revenue += sd.revenue;//销售额
    return *this;
}
```

假如一个Sales_data类对象book调用combine函数，book的地址被隐式地传入this指针。

**return语句中解引用this获得对象book，因为conbine模仿的是+=运算符，所以返回类型为引用类型才能返回一个左值**

## 构造函数

构造函数的任务是初始化类对象的数据成员

**构造函数没有返回类型，且与类同名**

**构造函数不能被声明为const！因为创建const类对象的过程中，直到构造函数完成初始化，类对象才能获得const属性！所以因此，构造函数可以向const类对象成员中写值**

**在参数列表后面添加“=default”可以声明为默认构造函数**

**如果一个构造函数没有任何形参，也没有构造函数初始值列表，那么它等同于合成的默认构造函数**

**当某个数据成员被构造函数初始值列表忽略时，它将以合成默认构造函数相同的方式隐式初始化**

**构造函数不应该轻易覆盖掉类内初始值，除非新赋的值与原值不同**

**构造函数一旦开始执行，没有出现在构造函数初始值列表的数据将会执行同合成默认构造函数一致的初始化行为。因此，如果成员是引用类型或者常量就必须有构造函数初始值列表或者类内初始值**

```c++
Sales_data(istream&is)//该函数没有构造函数初始值列表,函数开始执行时，数据成员以及进行同合成默认构造函数一致的初始化行为
{
    read(is,*this);//利用read函数改变数据成员的值
}
```

**构造函数初始值列表中初始值的顺序与初始化的顺序无关，初始化的顺序是由类定义中出现的顺序决定的**

```c++
class X
{
    int i;
    int j;
public:
    X(int val):j(val),i(j){}//先使用j初始化i，但是j此时还没有被初始化，因此j的值是未定义的，而不是val！但是行为是合法的，再用val初始化j
};
X x(90);
cout << x.i << endl << x.j;//输出i的值为不确定的值，j的值为90
```

**如果一个构造函数中，所有的形参都有默认实参，则它就相当于默认构造函数！在创建对象时不能使用调用运算符！**

```c++
struct Sales_data
{

private:
    string bookNo;
    double price = 0;
    unsigned int units_sold = 0;
    double revenue = 0;

public:

    Sales_data(string str = " ") :bookNo(str) {}//相当于默认构造函数
    Sales_data(string str,double p,unsigned u):bookNo(str),price(p),units_sold(u){}
    Sales_data(std::istream& is);
    string isbn ()const { return bookNo; }
};

Sales_data sd;//调用接受一个string参数版本的构造函数
Sales_data sd_2();//声明了一个返回Sales_data类型的函数！
```

### 默认构造函数：

当对象被默认初始化或者值初始化时自动执行默认构造函数

### 合成的默认构造函数：

如果我们没有显式地定义构造函数（只有这个情况时），那么编译器会隐式地定义一个默认构造函数，称之为合成的默认构造函数

**合成的默认构造函数规则：**

- 如果存在类内初始值，用它来初始化成员
- 否则，默认初始化该成员（**定义在块中的内置类型或内置复合类型成员的默认初始化值是不确定的**）

### 委托构造函数：C++11新标准，是初始值列表的拓展功能

一个委托构造函数使用它所属类的其他的构造函数执行它自己的初始化过程，或者说它把它自己的一些（或者全部）职责委托给了其他构造函数

**构造函数初始值列表只有一个入口，那就是类名本身，类名后面紧跟着圆括号括起来的参数列表，参数列表必须与类中的另外一个构造函数匹配**

```c++
struct Sales_data
{

private:
    string bookNo;
    double price = 0;
    unsigned int units_sold = 0;

public:
//四个普通构造函数
    Sales_data(string str,double p,unsigned u):bookNo(str),price(p),units_sold(u){}//构造函数1
    Sales_data(std::istream& is){read(is,*this);}//构造函数2
 //委托构造函数
    Sales_data():Sales_data(" ",0,0){}//默认构造函数，委托给构造函数1
    Sales_data(string s):Sales_data(s,0,0){}//委托给构造函数1
    Sales_data(istream& is):Sales_data()//先委托给默认构造函数，默认构造函数又委托给构造函数1，当这些委托的构造函数执行完成后，接着执行istream&构造函数体的内容
    {
        read(is,*this);
    }//注意！此处并不是委托给构造函数2！

};
```

**当一个构造函数委托给另一个构造函数时，受委托的构造函数的初始值列表和函数体被依次执行，执行完后才会将控制权交还给委托者的函数体**

### 转换构造函数：

什么样的构造函数能成为转换构造函数：

- 只有一个形参的构造函数
- 拥有多个形参的构造函数，但是没有默认实参的形参（**只能是第一个形参**）个数小于等于1个（也就是说可以全部都有默认实参）。此时也只有第一个参数的类型能够转换成所属的类类型。因为省略实参采用默认实参时只能省略形参列表尾部的实参！

```c++
struct Sales_data
{
private:
    string bookNo;
    double price = 0;
    unsigned int units_sold = 0;

public:

    Sales_data(string str) :bookNo(str) {}


};
string str_name = "JOJO's amzing adventure";
Sales_data sd("APEX LEGENS");//调用构造函数创建对象
sd = str_name;//正确！string隐式转换成Sales_data
```

**例子见类型转换隐式转换部分，还有个比如接受单参数const char\*类型的string构造函数：string str("zxmhs!");将C风格字符串隐式转换成string**

**抑制构造函数定义的隐式转换：将构造函数声明为explicit，该关键字只对转换构造函数生效。且只能再类内声明构造函数时使用explicit关键字。一个例子是接受一个容量参数的vector构造函数**

**explicit构造函数只能用于直接初始化！**

```c++
struct Sales_data
{
private:
    string bookNo;
    double price = 0;
    unsigned int units_sold = 0;

public:

    explicit Sales_data(string str) :bookNo(str) {}


};
string str_name = "JOJO's amzing adventure";
Sales_data sd(str_name);//正确！调用explicit构造函数创建对象
sd = str_name;//错误！explicit构造函数只能用于直接初始化！
```

**虽然explicit构造函数不能用于隐式转换过程，但是我们可以强制进行转换！**

```c++


explicit Sales_data(string str) :bookNo(str) {}//explicit构造函数


string str_name = "JOJO's amzing adventure";
Sales_data sd(str_name);//正确！调用explicit构造函数创建对象
sd = str_name;//错误！explicit构造函数只能用于直接初始化！
sd = static_cast<Sales_data>(str_name);//正确！强制类型转换
```

**优缺点：**必须通过显示的初始化，可以保证构造函数的数据成员的安全性，但构造函数的灵活性丧失

## 访问控制与封装：

**使用访问说明符来加强类的封装性：public、private**

**定义在private说明符之后的成员只能被类的成员函数访问**

**作为接口的一部分，构造函数和部分成员函数（给类的使用者使用的函数）应该紧跟在public后面；而数据成员和作为细节实现部分的函数（比如返回Sales_data中的平均售价的函数）应该跟在private后面**

一个类可以包含很多个访问说明符，一个访问说明符也可以出现很多次

**关键字struct和class的区别：struct的默认访问权限是public的，class的默认访问权限是private的。这是它们的唯一区别**

### 封装的含义：

封装是实现与接口的分离。它隐藏了类型的实现细节。（在C++中，封装是通过将实现放在一个类的私有部分来实现的）

封装有两个重要的优点：

- 确保用户代码不会无意间破坏封装对象的状态
- 被封装的类的具体实现细节可以随时改变，而无须调整用户级别的代码

### 友元：

有时候类外部的接口函数需要用到类的私有数据成员，就需要这个**接口函数声明为类的友元函数，只需要在函数声明前添加friend关键字**

**类的友元类或者友元函数可以访问它的私有成员**

**友元函数的声明中不可以加上默认参数！！！！！！！！！！！！！！！！！！！！！！！！！但是定义或者其他声明中带了的话依然管用**

**友元声明不属于类的一部分，不受访问说明符的影响！但是只能出现在类内部**

**一般来说，最好在类开始前或者结束前集中集中友元声明**

**友元声明仅仅制定了访问权限，而非一个通常意义上的函数声明，要想调用函数，还必须进行普通的函数声明！**

**友元会造成类封装性和可维护性下降**

**友元函数可以定义在类内部，这样的函数是隐式内联的。但是即使定义在类内部也仅仅指明了访问权限，还需要在类的外部进行普通的函数声明！**

```c++
struct X
{
    friend void f(){/*定义在类X内部的函数体*/}
    void clear(f();)//X的成员函数clear调用函数f。错误！因为f并未进行普通的函数声明
    void g();
    void h();
}
void X::g() { return f(); }//错误！因为f并未进行普通的函数声明
void f();//f的声明
void X::h() { return f(); }//正确！因为f已经进行了普通的函数声明
```

**友元不具有传递性！！！即A是B的友元，C是A的友元，但是C不能访问B的内容！！！**
**声明重载函数为友元时，必须针对每个重载函数的声明都做一次友元声明**
**可以令另一个类的某个成员函数为友元：**

1. **首先定义一个类A，其中声明需要作为友元的函数func，但是不能定义它。在func使用类B的成员之前必须先声明类B**
2. **接下来定义类B，包括多func的友元声明**
3. **最后定义func，此时它才能使用类B的私有成员（也就是func需要在类A的外部定义）**

```c++
class Screen;
class Window_mgr
{
private:
    std::vector<Screen> screens;
public:
    void clear(std::vector<Screen>::size_type sz);
};

class Screen
{
    friend void Window_mgr::clear(std::vector<Screen>::size_type sz);
public:
    using pos = std::string::size_type;

private:
    std::string contents;
    pos ht = 0;
    pos wd = 0;
    pos cursor = 0;
};

void Window_mgr::clear(std::vector<Screen>::size_type sz)
{
    Screen& s = screens[sz];
    s.contents = string(s.contents.size(), ' ');
}
```

class Screen

### 可变数据成员：mutable

**可变数据成员永远不会是一个常量，**即使它是const对象的成员。因此，**一个const成员函数可以改变一个可变成员的值**

### 成员嵌套调用时this指针的传递：

当一个成员调用另一个成员时，this指针在其中隐式地传递

```c++
Screen& display(std::ostream os)
{
    do_display(os);return *this;
}
void do_display(std::ostream os) const//该函数中，this指针是指向常量的
{
    os << contents;
}
```

**在上面地代码中，调用display时，this指针是指向非常量的，进入函数体内调用do_display时，this指针隐式地从指向非常量的指针转换成指向常量的指针（类型转换隐式转换部分），类似于一下代码：（假设调用的对象为scr）**

```c++
Screen& display(std::ostream os，Screen*this_1 = &scr)//&scr作为隐式的this指针参数，将地址传递给this指针
{
    do_display(os,this);return *this;//调用do_display时，将this_1指向的地址（非常量的scr的地址）传递给了do_display函数中的隐式形参指向常量的this_2指针
}
void do_display(std::ostream os，const Screen *this_2 = &scr) const//该函数中，this指针是指向常量的
{
    os << contents;
}
```

## 类的作用域

访问类的普通的数据和函数成员只能由对象、引用或者指针使用成员访问运算符来访问。**对于类类型成员则使用作用域运算符访问**

```c++
class Screen
{

public:
    using pos = std::string::size_type;

private:
    std::string contents;
    pos ht = 0;
    pos wd = 0;
    pos cursor = 0;
};

Screen::pos hight = 24；//访问类的类类型成员
```

**一个类就是一个作用域**

**一旦遇到了类名，定义的剩余部分就都在该类的作用域内了，这里的剩余部分包括参数列表和函数体，但是不包括返回类型。所以如果返回类型是该类定义的某个类型，则需要在返回类型上单独使用一次作用域运算符**

```c++
class Screen
{

public:
    using pos = std::string::size_type;


private:
    std::string contents;
    pos ht = 0;
    pos wd = 0;
    pos cursor = 0;
};
pos Screen::add();//错误！pos未定义！从函数名开始才进入Screen类的作用域
Screen::pos Screen::divi();//正确！第一个Screen::指定返回类型的作用域，第二个则指定后续剩余部分包括形参列表与函数体的作用域
```

内层作用域可以覆盖外层作用域中定义的名字，即使该名字已经在内层作用域中使用过。**但是无法覆盖外层作用域中定义的已经在内层使用过的类型别名！（未使用的类型别名可以覆盖）就算类中的类型别名语句与外层作用域中的语句一模一样也是非法的！（VS2022中已不存在此规则，可以覆盖类型别名）**

### 名字查找与类的作用域：

**名字查找过程：**

1. 首先在名字所在的作用域中寻找其声明语句，只考虑名字使用之前出现的声明
2. 如果没找到，继续到外层作用域查找
3. 如果最终没有找到匹配的声明，则程序报错

对于定义在类内部的成员函数来说，名字查找过程与上述规则有所区别：**编译器先编译成员声明，然后才轮到成员函数体。所以即使数据成员的声明在某个函数体之后，这个函数体也能调用这些声明在它之后数据成员**

1. 首先在函数体内寻找其声明，只考虑名字使用之前的声明
2. 如果没找到，继续到类中继续查找，这是类的整个作用域中的成员都可以被考虑
3. 如果类内也没找到，在成员函数定义之前的作用域内继续查找

**如果成员函数体内的名字隐藏了类内的同名成员，我们仍然可以显示使用this指针或类作用域运算符使用该同名成员**

## 聚合类：

**如果一个类满足以下条件，则它是聚合的：**

- 所有成员都是public的
- 没有定义任何构造函数
- 没有类内初始值
- 没有基类，也没有virtual函数

初始化聚合类对象时可以采用花括号括起来的成员初始值列表，初始值的顺序必须与声明的一致。如果初始值列表中初始值数量少于成员数量，则后面的成员被值初始化

## 字面值常量类：

**数据成员都是字面值类型的聚合类是字面值常量类。如果一个类不是聚合类，但是它符合下述要求，也算字面值常量类：**

- **数据成员必须都是字面值类型**
- **类必须至少含有一个constexpr函数**
- **如果一个数据成员含有类内初始值，则内置类型成员的初始值必须是一条常量表达式；或者如果成员属于某种类类型，则初始值必须使用成员自己的constexpr构造函数**
- **类必须使用析构函数的默认定义，该成员负责销毁类的对象**

## constexpr构造函数：

**尽管构造函数不能是const的，但是字面值常量类的构造函数可以是constexpr函数。事实上，一个字面值常量类至少提供一个constexpr构造函数**

**constexpr构造函数可以声明成=default的形式或者是删除函数的形式（P449）。否则，constexpr构造函数必须既符合构造函数的要求（不能包含返回语句）又符合constexpr函数的要求（唯一能拥有的可执行语句就是返回语句，注意，词此条规则在VS2022中已失效），所以constexpr构造函数的函数体一般来说是空的**

**constexpr构造函数必须初始化所有数据成员，初始值或者使用constexpr构造函数，或者是一条常量表达式**

## 类的静态成员：

类的静态成员与类相关联，而不是与类的对象相联

**类的静态成员被所有类的对象共享**

**类的静态成员函数也不与任何对象绑定在一起，因此没有隐式的this指针参数，自然也不能声明为const函数**

**我们使用类的作用域运算符来访问类的静态成员，也可以在某个对象上使用成员访问运算符。类的成员函数不需要使用类的作用域运算符就可以使用类的静态成员**

**在类的外部定义静态成员函数时，不能使用static关键字，此关键字只能出现在类内部的声明语句中**

**类的静态成员并不是在创建类的对象时被定义的，这意味着它们不是被构造函数初始化的。而且一般来说，我们不能再类内部初始化静态成员！在类内只能做声明**

**必须在类外部定义和初始化静态成员，类的静态成员定义于任何函数之外，一旦被定义就一直存在于程序的整个生命周期**

**定义类的静态成员时，可以访问所属类的私有成员！因为比较类的静态成员也是类自身的一部分！**

**想要确保只定义一次类的静态成员，一般将类的静态成员定义存放在头文件中**

### 静态成员的类内初始化：

尽管不推荐这样做，但是我们仍然可以为静态成员提供**const整数类型的类内初始值**，不过要求**静态成员必须是字面值常量类型的constexpr（或者const），初始值必须是常量表达式**

**这样的静态成员本身就是一个常量表达式，能用于所有适用常量表达式的地方，比如数组的维度**

**如果一个静态成员的应用场景仅限于编译器可以替换它的值的情况，则它不需要在类外额外定义。否则必须提供一条定义语句**

```c++
class XXX
{
    static constexpr int per = 30;//一条提供了类内初始值的静态成员
}
int ia[per];//正确！可以将per替换为30，不需要额外的定义语句
```

```c++
class XXX
{
    static constexpr int per = 30;//一条提供了类内初始值的静态成员
}
void func(const int&){/*......*/}
func(per);//错误！func(30)与func(per)不等价！因为参数类型为const int&，此时需要一条额外的定义语句
constexpr int XXX::per;//类外的定义语句，初始值已经在类内提供，则这里可以省略了
func(per);//正确！有了额外的定义语句
```

**为了安全起见，既是一个常量静态数据成员在类内被初始化了，在外部也应该提供定义语句**

**在类内对静态的vector成员使用非默认构造函数（比如指定容量）也算进行类内初始化！**

### 仅限静态成员的特殊场景：

**静态成员可以是不完全类型！因此类的成员可以是它本身的类型的静态成员**

**静态成员可以作为默认实参，非静态数据成员不能作为默认实参！因为非静态数据成员的值本身就是对象的一部分，作为默认实参无法真正提供一个对象以便从中获取成员的值**
